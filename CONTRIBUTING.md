# Contributing

There are no maintainers. There is no roadmap. There is no official version.

This is not abandonment — it is design.

## How this works

The framework evolves through forks, not pull requests to a central authority. If you disagree with something, change it. If your version is better, people will use it. The best ideas will propagate. The worst will be ignored.

This is how open protocols work. This is how they survive.

## Ways to contribute

### Fork it
Make your own version. Add what is missing. Remove what is broken. Publish it anywhere — GitHub, GitLab, IPFS, Arweave, Radicle, your own server. Link back if you want. Don't if you don't.

### Translate it
Every language is a new seed in a new ecosystem. Translations are among the highest-impact contributions. If you speak a language not yet represented, translate the framework and submit it as a pull request, or fork and publish independently.

### Build the infrastructure
The framework describes a system. Someone has to build it.
- Smart contracts for governance, reputation, and treasury
- Decentralized identity integrations
- Voting and proposal interfaces
- Working group coordination tools
- Translation layers between existing DAOs and this framework

Code repositories are welcome. Link them. Reference them. Invite others to join.

### Critique it
Find the weak points. Publish your analysis. Dissent is contribution. A framework that cannot withstand criticism does not deserve to spread.

Open an issue. Write a response document. Publish a counter-proposal. All of these strengthen the commons.

### Distribute it
Share it in communities that would benefit. Translate it for audiences that cannot read English. Pin it to IPFS. Inscribe it on Bitcoin. Print it and hand it to someone.

See [SEED.md](SEED.md) for the distribution strategy.

### Start a working group
Pick a focus area (climate, health, identity, economic justice — whatever moves you). Gather a few people who care. Start coordinating. Document your process. Publish your results.

You do not need permission. There is no one to ask.

## What to avoid

- **Centralization.** Do not create a "foundation" or "headquarters" or "official version." The moment one exists, it becomes a target and a bottleneck.
- **Branding and identity.** This framework is deliberately ownerless. Resist the urge to name it after yourself, attach your logo, or claim authorship of forks. Ideas spread further without egos attached.
- **Token sales.** This is not a product. It is not an investment opportunity. Anyone launching a "Framework Token" ICO is misusing the work.
- **Gatekeeping.** There are no gatekeepers. Do not become one.

## Pull request guidelines

If you submit a pull request to this repository (or any fork accepting PRs):

- Clear, specific changes are easier to merge than sweeping rewrites
- Explain the reasoning behind the change, not just the change itself
- Translation PRs should preserve the meaning, tone, and structure of the original
- Technical additions (smart contract specs, protocol details) should include references to existing implementations where possible

## A note on anonymity

The framework is anonymous by design. Contributors are welcome to remain anonymous. If you wish to be credited, that is your choice — but no one is required to attach their name to this work.

The ideas matter. The identities do not.
